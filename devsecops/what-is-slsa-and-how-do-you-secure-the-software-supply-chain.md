# What is SLSA and how do you secure the software supply chain?

**Short answer:** SLSA (Supply-chain Levels for Software Artifacts) is a tiered framework for proving how an artifact was built. Its core idea is verifiable provenance: a signed statement, produced by the build platform rather than the builder, saying which source commit and which build definition produced this exact digest. Supply-chain security then means verifying that provenance at deploy time and refusing anything that cannot prove its origin.

## Detail

**The levels (SLSA v1.1 Build track).** v1.1 became the approved specification in April 2025; it kept v1.0's levels unchanged and tightened the language around isolation, hermeticity, and provenance authenticity. The Build track is the only stable track - Source, Dependencies, and Verification tracks are still in draft, with the Source track landing in the v1.2 line.

| Level | Requirement                                                                                       |
| ----- | ------------------------------------------------------------------------------------------------- |
| L1    | Provenance exists and is available to consumers                                                   |
| L2    | Provenance is signed and generated by a hosted build platform                                     |
| L3    | Builds run in isolated, ephemeral environments; provenance is unforgeable by the build's own code |

L3 is the meaningful jump: a compromised build script cannot mint provenance for itself because the signing identity belongs to the platform, not to the job.

**The threats it addresses** map to the classic incidents: source tampering (Codecov), dependency substitution and typosquatting, compromised build systems (SolarWinds), and registry tampering. Note that SLSA says nothing about whether the code is _good_ - it proves origin, not quality.

**The practical control set:**

- Protected branches, required review, and signed commits for source integrity.
- Pinned, hash-verified dependencies (lock files committed, `--frozen-lockfile`, internal proxy/mirror) to stop substitution.
- Ephemeral, hermetic builds on a hosted runner with short-lived OIDC credentials - no long-lived registry passwords in CI.
- Keyless signing of artifacts, SBOM and provenance attached as attestations.
- Admission control in the cluster verifying signature _and_ provenance predicate before a Pod runs.

**Verify at the boundary you control.** Signing without verification is theatre. The gate belongs in the cluster (Kyverno/OPA Gatekeeper image verification) or in the deployment pipeline, and it must fail closed.

## Example

```yaml
# Kyverno: only run images built by our GitHub org's workflows, verified keylessly
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: verify-slsa-provenance
spec:
  # verifyImages rules fail closed by default - an image whose attestation cannot be
  # verified is rejected. (Note: spec.validationFailureAction was deprecated in Kyverno 1.13;
  # for validate rules the setting now lives at spec.rules[].validate.failureAction.)
  rules:
    - name: check-provenance
      match:
        any:
          - resources: { kinds: [Pod] }
      verifyImages:
        - imageReferences: ["ghcr.io/acme/*"]
          attestations:
            - type: https://slsa.dev/provenance/v1
              attestors:
                - entries:
                    - keyless:
                        issuer: https://token.actions.githubusercontent.com
                        subject: "https://github.com/acme/*"
              conditions:
                - all:
                    - key: "{{ buildDefinition.externalParameters.workflow.ref }}"
                      operator: Equals
                      value: "refs/heads/main"
```

## Interview tips

- The one-sentence definition to have ready: "provenance generated by the build platform, not by the build."
- Tie levels to incidents - SolarWinds for build-system compromise, Codecov for source/CI tampering.
- The follow-up is always "how do you verify?" - admission control that fails closed, plus what you do for third-party images that have no provenance (mirror, scan, and pin).
